## Name

**The Only Thing at the Bottom**

The subtitle *30 missions to Mars* does the searchable work and belongs in the short
description and the capsule art rather than the store name — Steam truncates long names
in the library, the wishlist mail and the friends' activity feed, and it is the first
half that survives.

## About This Game

*Steam BBCode. Paste directly into the "About This Game" field.*

```
[h2]Three parties share one canyon. You fly for all of them.[/h2]

A scientific outpost got to Coprates Chasma first. Two extraction charters did not, and
neither of them intends to leave. You are on the end of a telemetry link — thrust, vector
angle, attitude, all remote — flying cargo runs for whoever is paying.

[b]What you deliver stays in the canyon.[/b] Every pad you land on, every deck and gantry
and bore you supply, is still standing on the next run. By mission twenty-nine you are
threading a corridor you spent twenty-eight missions helping to close.

[h2]The canyon is yours[/h2]

[list]
[*][b]Rolled once, then frozen.[/b] A seed is drawn on first launch and kept for the whole
campaign — no two players fly the same chasm.
[*][b]The colony grows from your own scores.[/b] Not a scripted set of unlocks: the
settlement spreads across the rock as branching filaments, and how far it reaches is
decided by how well you landed.
[*][b]Deterministic to the frame.[/b] Same seed, same layout, same hazard phase. A retry
replays exactly what beat you, which is the only way a hard landing game can be fair.
[/list]

[h2]Three airframes, three ways to fly[/h2]

Same three inputs on all of them. What the inputs [i]do[/i] is the difference:

[list]
[*][b]TD-4 LANDER[/b] — manual attitude. Rotation stays live under main thrust, and
fighting the two against each other is the whole skill.
[*][b]KD-9 HAULER[/b] — locked attitude, twin vectoring. No attitude to fight; you simply
cannot go sideways without also going up.
[*][b]HD-7 SIDEWINDER[/b] — dedicated side jets. Genuinely independent axes: it holds
altitude while it translates.
[/list]

Payload mass is real. It is added to the dry mass, so thrust response and rotation both
fall with a heavy manifest — and you can see the load grow on the deck.

[h2]Landing is scored, not merely survived[/h2]

Every touchdown is ranked S to C on fuel remaining, how softly you arrived, and how near
the middle of the deck you put it. Softness is measured on combined speed, so lateral
drift costs you even when the descent rate is perfect. Delivering to the wrong pad is its
own kind of failure — corporate clients pay for addresses.

[h2]Nobody in this canyon talks the same way[/h2]

Your clients brief you between runs, and what each one calls you is the cheapest
characterisation in the game. The outpost calls you [i]navigator[/i], after the navigation
mast you built them. The deep charter calls you [i]tin can[/i] — the trade word for
whatever turns up on the end of a link. The third emits a centile and files no further
action.

The game never names what is on the other end of that link. That is the point of it.

[h2]A score that is playing your mission[/h2]

Five voices, one chord progression per charter, and a mission callsign that is also the
rhythm — twenty-nine grooves, none of them hand-authored. The mix follows the vehicle
down: the canyon takes voices away as you descend past the rim.

[h2][/h2]
Twenty-nine deliveries, and a thirtieth flight that is not one.
```

# Store copy — itch.io

Shorter, and it leads with the thing itch rewards: it runs in the browser, right now.

> **Play it in the tab you are already in.** A 2.5D physics lander in a Martian chasm
> shared by three parties who do not like each other. Twenty-nine cargo runs, flown on a
> remote telemetry link. Everything you deliver stays in the canyon — so the corridor gets
> tighter, and it is your own deliveries that tighten it.
>
> Your canyon is rolled on first load and kept: no two players fly the same chasm, and the
> colony that grows across it is shaped by your own landing scores. No install, no account,
> and a campaign survives a reload.
>
> **Controls** — `←` `→` steer, `↑` / `W` / `Space` for the main engine, `P` to pause. On a
> phone, the screen is three zones: left, middle, right.

Set **Kind of project: HTML**, tick *This file will be played in the browser*, and set the
viewport to 1280×720 with fullscreen enabled. Put the web build first in the uploads list
so the player lands above the fold.

Upload `itch/cover-630x500.png` as the cover image — it is the only required image, and it
is what every browse and search listing shows. Screenshots are the same files Steam gets;
[README](README.md) has the order worth using here, which is not Steam's.

# Before any of this goes live

Four things that are true about this project specifically, and worth deciding on
deliberately rather than discovering at submission.

1. **Steam needs a downloadable build.** This is a Vite/WebGL game; Steam will not host a
   browser build. A [Tauri](https://tauri.app) wrapper is the small option (~10 MB, uses
   the system webview); Electron is the safe one (~150 MB, ships its own Chromium and so
   cannot be broken by someone's OS webview). Either way it is a real port task with real
   testing on three platforms — not a packaging step.
2. **Steam Direct is $100 per app**, recoupable against revenue, and the store page must be
   live for **30 days** before you are allowed to release. Plan the date backwards from
   that.
3. **The repo is MIT**, and the README says the code, the canyon and the campaign are all
   yours to take. That is entirely compatible with selling on Steam — but anyone may
   legally build and redistribute the same game. Plenty of projects ship this way
   deliberately; it is only a problem if it surprises you later.
4. **It is free on itch.** Releasing the same build paid on Steam is normal and fine, but
   decide the story now — "free in the browser, paid for the desktop build with
   achievements and controller support" is a position; silence is not.
